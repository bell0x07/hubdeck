# M005S: 5xFader (PID 0x0200)

M0 family, see [m0-family.md](m0-family.md).

- **Descriptor [hw]:** get-feature IDs 0x2d–0x34 and 0x36. It has 0x33 (slider values), which Knob and Roller don't.
- **Reads [hw]:** firmware 01.00.05.00, serial `MHFD05AA42…`, brightness (0x32) `05 64 64 64 64 64`, mode (0x34) `05 09 09 09 09 09` = rainbow, positions (0x33) `05 00 00 00 00 00` with all faders down.
- **Positions [hw]:** report `01 2a 07 00 | 02 05 s1 s2 s3 s4 s5`, each 0 (bottom) to 100 (top). It's sent about every 20 ms while a fader moves (~50/s) and always carries all five positions.
- **Numbering [hw]:** faders 1–5 run left to right, matching the LED index.
- **Lighting [up]:** 5 zones, LED module `0x01`, index 0–4 or `ff` for all. White with value-following brightness was checked on hardware.

## Connecting [hw]

The Base only detects a newly attached module when it powers up. Removing a module is noticed immediately, but after inserting the Faders, Windows didn't see them, and they had no lights, until the Base's USB cable was unplugged and plugged back in. hubdeck reconnects every module by itself after that.

## hubdeck behaviour

- The first report after connecting only records where each fader sits; it's never applied.
- **Soft takeover:** a fader controls its target only after it reaches (±4) or passes the target's current value, so moving it never makes the volume jump. Confirmed on hardware: it took over system volume at 46 when the volume was 50.
- If the target's value is unknown (e.g. an app that isn't running), the fader doesn't take over.
