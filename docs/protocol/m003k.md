# M003K: 3xKnob (PID 0x0202)

M0 family, see [m0-family.md](m0-family.md).

- **Descriptor [hw]:** get-feature IDs 0x2d–0x32, 0x34 and 0x36.
- **Reads [hw]:** firmware 01.00.05.00, serial `MHKB03AA22…`, brightness (0x32) `03 64 64 64`, mode (0x34) `03 09 09 09` = rainbow on all three.
- **Rotation [hw]:** report `01 2a 05 00 | 00 03 d1 d2 d3`. Each byte is `01` = clockwise, `00` = counter-clockwise, `ff` = no change. One report per detent; only the moved knob's byte changes.
- **Press [hw]:** report `01 2a 05 00 | 03 03 p1 p2 p3`, `01` while held, `00` on release. Down and up are both reported, one report each.
- **Lighting [hw]:** 3 zones, LED module `0x02`, index 0–2 or `ff` for all.

## Numbering [hw]

The input index and the LED index are the **same**. Each was checked by turning a knob and seeing which knob's LED colour belonged to it. Mounted horizontally (one knob on top):

```
      [3]
  [1]     [2]        1 = bottom-left, 2 = bottom-right, 3 = top
```

hubdeck uses this order ("knob 1" = the module's first control). It stays the same if the module is mounted rotated; only the physical positions move.

> An earlier version of these notes listed a different input order. That came from misreading the order of actions in a test session. A later test, turning a knob and watching which one adjusted, settled it.

## Unknown

- The number of physical LEDs per knob (one colour per knob in the protocol)
- Whether turning while pressed changes the events (one report carries either rotation or press)
